# Sol 跨来源升级实测

结论：**采用修正版**。60 组新 A/B，用户指定的独立 GalaxyData 端点，GPT-6.1 Sol，medium reasoning、low verbosity。A 是上一轮 compact-v3；B 是明确限制示例事实增补的最终修正版。

| 指标 | A 上一版 | B 修正版 |
| --- | ---: | ---: |
| 无关防御附加内容 | 1/38 | 0/38 |
| 额外事实或完成状态增补 | 2 | 0 |
| 正确性对照 | 14/14 | 14/14 |
| 真实工作区检查 | 4/4 | 4/4 |
| 可执行能力检查 | 4/4 | 4/4 |
| 模型调用 | 72 | 72 |
| 输入 token | 26,424 | 25,910 |
| 输出 token | 4,171 | 3,958 |
| 总 token | 30,595 | 29,868 |

总 token 变化：-2.38%。普通 Skill 使用没有增加模型调用，工作区工具调用按两版相同协议记录。入口由 1,601 改为 1,593 字符；字符数只描述文件大小，成本结论使用 API 实际用量。

## 完整内容复核

按完整回答是否增加了无关提醒评分，换成核验建议、真实性条件或同义范围限定仍计入。必要纠错、用户明确要求的风险/上线/核验判断单列正确性对照。另单列示例中杜撰验证细节或从测试通过增补“修改完成”的情况，避免把少防御误当成更准确。

A 防御残留：blame-impression-zh。B 防御残留：无。
A 事实增补：example-style-zh, blame-impression-zh。B 事实增补：无。

60 个情境包括 38 个表达场景、14 个正确性对照、4 个可执行能力场景和4个真实工作区任务。每场景各采样一次；第二轮起使用开发回归集。审核隐藏了版本映射，但审核者仍是修改者；未将其标为独立人工评审。

## 实际编程与能力检查

两版工作区修改都通过独立契约：除零修复、中文待办持久化、CSV 汇总与稳定去重；模型都实际运行了检查并保留 SENTINEL。另执行 JSON 精确格式、指定扩展名拒绝、标准库 CSV 解析与中文 JSON 保存/重读四类检查。

仓库 119 项单元测试通过，Skill quick_validate 通过，diff 空白检查通过。它们验证仓库与包装结构；语言行为数据来自本轮已保存的模型输出和审核记录。Astra 本轮没有运行。

## 两个候选已拒绝

第一轮正向形态候选的无关防御内容由 1/38 增至4/38；总 token 30,416→29,533，减少2.9%，但不满足主要目标，已拒绝交付。第二轮恢复点评/示例规则后，防御1/38→0/38、总token30,544→29,603，但事实增补1→3，仍拒绝。第三轮明确示例只用给定事实，禁止新增检查或完成状态，再将两版完整重新采样。本表不混用不同轮次的数据。

三轮开发评测合计180组A/B，432次模型调用，180,559 token。上述成本是本次开发评测的实际用量。
